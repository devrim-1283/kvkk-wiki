## English

# Information Notice Checklist

This checklist is used to systematically verify that an information notice meets Articles 4 and 5 of the Disclosure Communiqué. If at least one item is marked "No", the notice **cannot be published** and must be corrected.

## 1. Identity of the Data Controller (Communiqué Art. 4/a)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 1 | Is the **full title** of the data controller stated explicitly? | | An abbreviated reference such as "the Company" is not sufficient |
| 2 | Is a complete address provided? | | District, street, no, town, city |
| 3 | Are contact channels (telephone, KEP, e-mail, web) included? | | Must be consistent with what is registered with the Registry |
| 4 | For a data controller not resident in Turkey, is the **representative**'s identity included? | | Reg. Art. 11/2 |
| 5 | Is the contact person's information included? | | Communiqué Art. 4 + Reg. Art. 11/4 |

## 2. Processing Purpose (Communiqué Art. 4/b, Art. 5/g)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 6 | Is the purpose **specific**? Are generic expressions ("commercial purpose", etc.) avoided? | | Communiqué Art. 5/g — vague expressions prohibited |
| 7 | Is the purpose **explicit**? | | Easily understandable to the data subject |
| 8 | Is the purpose **legitimate**? | | KVKK Art. 4(2)/c |
| 9 | If there are multiple purposes, are they enumerated separately? | | Not crammed into a single paragraph |
| 10 | Are catch-all expressions like "and any other purposes" avoided? | | Communiqué Art. 5/g — must not imply other purposes |

## 3. Legal Ground (Communiqué Art. 4/ç, Art. 5/h)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 11 | Does the legal ground refer to **a specific clause** of KVKK Art. 5(2)? | | "Under contract" is not sufficient; "KVKK Art. 5(2)/c — Necessity for the conclusion or performance of a contract" must be stated |
| 12 | If special-category data is involved, is the relevant clause of KVKK Art. 6(2)/(3) stated? | | Art. 6 requires its own analysis |
| 13 | Are the purposes that rely on explicit consent stated **separately**? | | Where consent is used, "KVKK Art. 5(1) first sentence" |
| 14 | Where multiple purposes have different legal grounds, is each purpose paired with its ground clearly? | | Mapping must be explicit |
| 15 | Are explicit consent and the legal ground used interchangeably? | | This must not occur |

## 4. Transfer (Communiqué Art. 4/c, Art. 5/ı)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 16 | Are the **recipients/recipient groups** of transfer specified? | | "Our business partners" is not enough; recipient categories clarified |
| 17 | Is each recipient group paired with a separate **transfer purpose**? | | Communiqué Art. 5/ı |
| 18 | Is the existence/absence of **cross-border transfer** stated explicitly? | | KVKK Art. 9 |
| 19 | If cross-border, are the recipient + country + KVKK Art. 9 legal basis (adequacy decision, standard contract, BCR, etc.) stated? | | Legal basis mandatory |
| 20 | Is the transfer consistent with the inventory (and the VERBİS notification)? | | Reg. Art. 5/d alignment |

## 5. Collection Method (Communiqué Art. 4/ç, Art. 5/i)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 21 | Is it stated **expressly** whether the data is collected by **automated** or **non-automated** means? | | Communiqué Art. 5/i — "expressly" |
| 22 | Is the collection channel (web, call center, paper, camera, etc.) stated? | | Operational clarity |
| 23 | If collection is mixed, is each channel's method stated? | | Multi-channel — multi-explanation |

## 6. KVKK Art. 11 Rights (Communiqué Art. 4/d)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 24 | Are KVKK Art. 11 rights enumerated as a **complete list** (a) through (ğ)? | | Incomplete enumeration breaches Communiqué Art. 5/j (incomplete information) |
| 25 | Are application channels (writing, KEP, system-registered e-mail, e-signature) stated? | | Application Communiqué Art. 5 |
| 26 | Is the 30-day response period mentioned? | | KVKK Art. 13 |
| 27 | Is detailed guidance for application (form, address) provided? | | Operational clarity |

## 7. Retention Period

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 28 | Is the retention period stated **numerically**? | | "As needed" is not sufficient |
| 29 | Is the period justified with reference to relevant legislation and business need? | | VUK, TTK, TBK, SGK, etc. |
| 30 | Is the period consistent with the inventory and retention-destruction policy? | | Internal consistency |

## 8. Wording, Language and Structure (Communiqué Art. 5/ğ, j)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 31 | Is the language **understandable, clear and simple**? | | Communiqué Art. 5/ğ |
| 32 | Are legal expressions written in a way an average reader can understand? | | In the official language? |
| 33 | Are there no incomplete or **misleading** statements? | | Communiqué Art. 5/j |
| 34 | Is the document professional in spelling, grammar and formatting? | | Corporate quality |
| 35 | Are document ID, version, date, and effective date present? | | Evidence and tracking |

## 9. Unit/Process Separation (Communiqué Art. 5/c)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 36 | Is this notice prepared for a **specific process/unit**? | | Communiqué Art. 5/c — separate per unit |
| 37 | Is it not a generic "company-wide information notice"? | | A single notice covering all processes is weak |
| 38 | Was it approved by the process owner and the KVKK Officer? | | Internal procedure |

## 10. Separation From Explicit Consent

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 39 | Where the processing requires explicit consent, is consent obtained **SEPARATELY**? | | Disclosure + consent must not be merged |
| 40 | Is consent-disclosure not merged into a single checkbox like "I read the information notice and accept"? | | Faulty implementation |
| 41 | For explicit consent, is there a separate screen/checkbox/signature? | | Operational separation |

## 11. VERBİS / Inventory Alignment (Reg. Art. 5/d)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 42 | Do **purposes** in the notice match those in the inventory? | | Internal consistency |
| 43 | Do **data categories** and the data subject group match the inventory? | | Internal consistency |
| 44 | Do **recipient groups** match the inventory and VERBİS notification? | | Reg. Art. 5/d |
| 45 | Is the **cross-border transfer** declaration consistent? | | Internal consistency |
| 46 | Does the **retention period** match the inventory? | | Internal consistency |

## 12. Burden of Proof (Communiqué Art. 5/e)

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 47 | Is an **evidence mechanism** in place for proving disclosure? | | Communiqué Art. 5/e |
| 48 | Web channel: are display logs (user, IP, time, text version) kept? | | Electronic record |
| 49 | Paper channel: is the signed copy in the archive? | | Physical record |
| 50 | Oral channel: is there a written supplementary document + delivery log? | | Supporting evidence |
| 51 | Call center: are IVR-announcement system log + voice recording captured? | | System record |

## 13. Operational Consistency

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 52 | Is disclosure performed at the **moment data is collected**? | | Communiqué Art. 5/b |
| 53 | Have the staff/touchpoints applied by the process owner been trained? | | Operational implementation |
| 54 | Is the information notice easy to **find** on the website (footer link, modal, etc.)? | | Accessibility |
| 55 | Are previous versions of the notice archived? | | Backwards-looking evidence |

## 14. Accessibility

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 56 | Is there screen-reader compatibility for visually impaired users? | | WCAG 2.1 AA target |
| 57 | Is it readable on mobile devices? | | Responsive |
| 58 | For mixed audiences, is an English version available? | | For multilingual organisations |

## 15. Approval and Versioning

| # | Check | Y/N | Note |
|---|-------|-----|------|
| 59 | Has the Legal Department approved it? | | Signature/approval record |
| 60 | Has the KVKK Officer approved it? | | Signature/approval record |
| 61 | Are version number, effective date, document ID assigned? | | Version management |
| 62 | Is the previous version archived (immutably)? | | Audit chain |

## 16. Outcome

| Outcome | Action |
|---------|--------|
| **62/62 Yes** | Publishable |
| **1-5 No** | Correct → re-evaluate |
| **6+ No** | Full revision with the Legal Department |
| **Critical (Art. 4 mandatory element missing)** | Take down → fix → re-approve |

## 17. Operational Use of the Checklist

### 17.1 For a new notice
- Drafting → checklist → Legal → KVKK Officer → publication

### 17.2 For existing-notice review
- Annual full revision: all notices scanned with this list
- When a Board decision is published: relevant notices re-evaluated
- Following a data subject complaint / Authority audit: relevant notice re-evaluated
